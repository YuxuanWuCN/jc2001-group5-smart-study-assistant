## 1. 一句话说明你要交付什么

**证明"考官在自己电脑上，照着两行命令，就能把这个系统跑起来"——并且说清楚为什么这是可能的。**

这一节是 PoC 评分项 **Documentation and Reproducibility** 与 **Reliability** 的直接证据。很多学生项目在这一节写成"我们部署在阿里云上，配置了 Nginx + Docker"，然后考官在离线考场上打不开——你们的情况恰好相反：**部署的极简性本身就是架构决策的成果，要把它讲成优势，而不是讲成"我们没做部署"。**

### 5.6.3 Deployment Procedure (300–400 words)

**写成分步命令清单**（这是全报告唯一应该出现命令的地方，因为这是部署说明不是源码）：

> ⚠️ **2026-10-25 安全审计**：仓库内曾提交的 `jc2001-group5-poc.zip` 因内嵌整改前的硬编码凭证快照，已移出仓库并隔离。发布版 ZIP 必须基于凭证整改后的 HEAD **重新打包**，打包前运行密钥扫描确认 0 命中，禁止直接分发旧档。

```
# 1. 解压
unzip jc2001-group5-poc.zip && cd jc2001-group5-poc

# 2. 建虚拟环境（可选但推荐）
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate      # macOS / Linux

# 3. 安装依赖
pip install -r requirements.txt

# 4. 启动
uvicorn backend.app.main:app --port 8000

# 5. 打开浏览器
# http://127.0.0.1:8000
```

**必须补一句**：整个流程**不超过 5 分钟**，且**在第 4 步之前不需要任何配置文件、环境变量或密钥**。这句话是全节的核心卖点。

**再补一段"我们实测过"**：在至少 2 台不同机器（不同 OS）上按此流程验证通过，记录日期。**要真做，不要编。**

## 6. 导师会问你的 3 个问题（准备好 30 秒答法）

**Q1. "你没有部署到服务器上，这算部署吗？"**
> 答：算，而且是刻意的。这门课的 PoC 是要在考官自己的机器上跑，不是给公网用户用。部署到云上对我们只有一个后果：考场断网就打不开。所以我们的部署目标是**零外部依赖的单进程可执行包**，一条 `uvicorn` 命令、5 分钟、不需要任何配置文件与密钥。**这是一个针对交付场景做的部署决策，不是没做部署。**

**Q2. "如果 8000 端口被占用怎么办？"**
> 答：`--port` 覆盖即可，ZIP 的 README 里写了。这也顺带解释了我们为什么用 `allow_origins=["*"]`——考官可能用任意端口打开页面，白名单会让本地调试处处报错（ADR-06，我们同时声明了生产化必须收紧）。

**Q3. "你的评估数据能复现吗？"**
> 答：**部分能。** 145 个测试和题库是完全可复现的，零外部依赖。MMLU 评估的原始 CSV 全部随仓库提供，但重跑评估需要 Neo4j 云实例，该实例的密码已按安全规范轮换，所以重跑不保证可用——我们把**结果快照 `final_systematic_report.csv`** 一并提交了，报告里所有数字都能追溯到这个文件。**我们没有把不可复现的部分藏起来，5.6.4 里列清楚了。**
