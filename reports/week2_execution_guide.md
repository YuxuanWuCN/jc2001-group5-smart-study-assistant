## 1. 本科生能力边界与课程考核基准声明

在 JC2001 课程中，考官（如 Dr. Mumtaz 与 Dr. Yu）评估的不是系统是否达到了工业级商业交付标准，而是**是否完整践行了经典软件工程规范**：
- **切忌企业级过度设计**：不需要搭建复杂的多集群 K8s、分布式消息队列、微服务拆分或前沿复杂的深度强化学习。这些不仅容易在导师答辩时被质疑真实性，而且会导致组员无法理解和维护。
- **突出本科生高质量工程规范**：
  1. 需求明确（用例清晰、有明确的前置条件和成功流）；
  2. 架构合理（标准的 UML 用例图、类图、顺序图，采用三层架构或经典 MVC）；
  3. 代码干净可运行（PEP8 规范、有必要的异常捕获、可一键在个人电脑启动）；
  4. 文档扎实连贯（40-60 页技术报告中，需求、架构、代码、测试能够环环相扣，相互呼应）。
- **时间与负荷可控**：每位组员在第二周的有效投入时间建议控制在 **4–8 小时**，既保证课程大作业质量，又不影响大家其他专业课的学习与生活。

## 4. 标准本科生级用例规约模板与示范（Use Case Specification）

JC2001 技术报告第 3 节明确要求：“Include appropriate use case diagram(s) and descriptions of the key use cases”。  
本科生课程推荐采用 **Cockburn 经典轻量规范模板**，结构清晰、逻辑严谨，既展现工程素养，又易于书写：

### 4.1 规范用例模板定义
- **用例编号 (Use Case ID)**：如 `UC-01`
- **用例名称 (Use Case Name)**：动宾短语（如：提交错题获取排雷诊断）
- **主要参与者 (Primary Actor)**：如 学生 (Student)
- **前置条件 (Pre-conditions)**：触发用例前系统必须满足的状态
- **后置条件 (Post-conditions)**：成功执行后系统的数据变更或输出
- **基本事件流 (Main Success Scenario)**：编号列出用户操作与系统响应（通常 4–6 步）
- **备选/异常流 (Extensions/Exceptions)**：偏离正常流时的处理逻辑（如输入格式错误、接口超时）

### 4.2 示范用例：UC-01 错题智能排雷与知识归因

```markdown
### 用例规约：UC-01 错题智能排雷与知识归因 (Intelligent Misconception Diagnosis)

- **用例编号**：UC-01
- **用例名称**：提交错题获取排雷诊断
- **主要参与者**：在校大学生（Student）
- **用例描述**：学生在自测过程中选错选项后，触发系统针对错选原因（Trap/易错点）进行针对性解析与知识关联诊断。
- **前置条件**：
  1. 学生已进入“专项刷题”模块并加载了当前学科的练习题；
  2. 后端诊断服务与知识图谱数据库处于正常运行状态。
- **后置条件**：
  1. 系统在界面右侧抽屉面板（Diagnostic Drawer）展示题目排雷报告；
  2. 学生的本次错题记录暂存于本地学情状态中，用于更新薄弱点雷达。

- **基本事件流 (Main Success Scenario)**：
  1. 学生阅读题干，点击选中一个错误的选项（例如误选了混淆选项 B）；
  2. 系统前端捕捉选中事件，向后端发送诊断请求：`POST /api/diagnose`（携带题目 ID 与用户所选选项）；
  3. 后端业务逻辑层接收请求，从题目元数据中提取选项 B 对应的预设错误诱因（Distractor Trap）；
  4. 业务层调用知识图谱服务，匹配该错误点所连边的核心知识概念（如：`Concept: 假设检验 P值原理`）；
  5. 后端组装诊断结果（错误根因、对应定理、避坑建议），并以 JSON 格式返回给前端；
  6. 前端动态展开右侧诊断抽屉，高亮呈现核心考点、错误诱因与解析内容；
  7. 学生阅读诊断后，可点击“向导师追问”或关闭抽屉继续下一题。

- **扩展/异常流 (Extensions)**：
  - *2a. 网络连接中断或后端服务未响应*：
    - 2a1. 前端等待 3 秒后超时，界面提示：“诊断服务暂时离线，已为你切换至本地离线提示模式”；
    - 2a2. 前端展示该题目本地自带的基础文本解析，不影响学生继续刷题。
  - *4a. 图谱中暂未检索到深度关联概念*：
    - 4a1. 系统启用通用大模型兜底诊断，根据题干与选项直接生成两句话的启发式提示。
```

```text

│   │   └── report.py        # 学情分析数据接口 (/api/report)
```

### 5.3 接口模型示例 (`app/models/schemas.py`)
```python
from pydantic import BaseModel
from typing import List, Optional

class QuestionOption(BaseModel):
    key: str           # "A", "B", "C", "D"
    text: str          # 选项文本

class QuizQuestion(BaseModel):
    id: str
    subject: str       # "法律职业资格", "统计学", "计算机网络"
    title: str         # 题干
    options: List[QuestionOption]
    answer: str        # 正确选项
    knowledge_point: str

class DiagnoseRequest(BaseModel):
    question_id: str
    selected_option: str

class DiagnoseResponse(BaseModel):
    is_correct: bool
    core_concept: str
    trap_analysis: str
    advice: str
    related_nodes: List[str] = []
```
