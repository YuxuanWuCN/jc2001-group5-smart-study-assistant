# 组会防身答案库 · Supervisor Q&A Defence Library

> **用途**：导师（Dr. Shahzad Mumtaz）组会追问时的标准答法。每条 30–60 秒可讲完。
> **原则**：① 先给结论再给理由；② 主动交出弱点（比被问出来强十倍）；③ 数字全部能追到仓库文件；④ 不知道就说不知道，不要编。
> **配套**：[`cycle3_master_plan.md`](cycle3_master_plan.md)（总计划）、[`cycle3_task_packs/README.md`](cycle3_task_packs/README.md)（分工）。

## 0. 三句定场话（任何提问前的开场锚点）

导师问的第一个问题往往是"你们这个项目到底做了什么"。**不要从技术栈讲起**，用这三句：

1. **一句话定义**：「We built a practice quiz tool whose feedback is attached to the *wrong option the student picked*, not to the question.」
2. **一句话差异**：「Quizlet only tells you right or wrong; a general LLM spoils the answer and can hallucinate the statute. We tell you which concept you mixed up and which prerequisite you are missing.」
3. **一句话边界**：「It runs fully offline on a single command, and it is a feasibility prototype with 12 questions and 36 traps — not a product.」

> 这三句是"去 AI 感"的核心武器：**有定义、有对比、有边界**。AI 生成的项目描述通常三样全无。

## 1. 第一类追问：「为什么做得这么复杂 / 这么像 AI 系统？」

### Q1.1 "This looks more like an AI agent system than a student project. Why so sophisticated?"

**答（40 秒）**：
> 因为复杂度不在功能数量上，而在**数据建模**上。我们的功能只有 8 个 API 端点、7 个用户可见功能，比一般的学生项目还少。真正花时间的是那 36 个陷阱的数据设计——每个错误选项都要能回答三个问题：错在哪、缺哪个前置知识、该记到哪个能力维度。
>
> 界面看起来"现代"，是因为我们**手写了 73 KB 的 CSS**（没有用组件库、没有用 Tailwind），视觉语言是自定义的，而不是拿来主义。但如果您看我们的架构，会发现它是刻意**简单**的：单进程、单端口、无数据库、无云依赖、一条命令跑起来。**复杂度在内容和约束里，不在炫技里。**

**如果导师追问"界面为什么做成这样"**：
> 三个教学决策：① 正确答案默认折叠（对抗 Answer Spoiling）；② 诊断做成右侧抽屉而不是弹窗（弹窗会盖住题目，学生没法对照原题看诊断）；③ 几乎没有装饰性动画（原则是 data over decoration）。

### Q1.2 "Did you use AI to build this? Be honest."

**答（30 秒）**：
> 用了，AI 在我们的工作流里承担了代码实现与文档初稿的一部分工作，这一点我们不隐瞒。但**判断是我们做的**：为什么砍掉多租户、为什么陷阱挂在选项而不是题目、为什么诊断必须是查表而不是模型推理——这三个决策决定了这个系统的样子，它们不是 AI 提出来的。**如果只是 AI 生成，它不会把两个负提升的 MMLU 结果留在报告里。**

> ⚠️ **诚实红线**：绝对不要说"完全没用 AI"（课程本身就在教 AI 辅助工程），也不要说"全是 AI 做的"。正确姿态是：**AI 是工具，判断和取舍是人的**。

### Q1.3 "Why not just use an LLM to diagnose misconceptions? LLMs are very good now."

**答（45 秒）**：
> 因为这个场景下"正确性"不能漂移。我们法学那道题的正确解析写着《民法典》第 152 条：自知道或应当知道撤销事由之日起一年内。如果让模型现场生成，它可能写成两年或三年——在教育场景里这是教学事故级错误。
>
> 查表的代价是只能覆盖预定义陷阱，收益是**正确性、可复现性、零边际成本、完全离线**。这个取舍我们在报告第 5.4.2 节画了一张对比表，**包括我们输掉的那一行**：开放问答场景下查表完全失效，而这正是我们选择闭式选择题界面的根本原因。

## 2. 第二类追问：「这东西到底解决了什么 Quizlet 和 ChatGPT 解决不了的问题？」

### Q2.1 "How is this different from Quizlet or ChatGPT?"

**答（40 秒）**：
> 三处不同，按重要性排序：
> 1. **反馈粒度**：Quizlet 的反馈挂在一道题上（对/错）；我们的反馈挂在**你选的那个错误选项**上。同一道题选 B 和选 C 得到的是完全不同的诊断。
> 2. **反馈内容**：ChatGPT 给的是完整解释（顺便剧透答案）；我们给的是四段结构——误区命名、错因、**缺失的前置知识**、能力维度归因。第三段是关键：它把"你错了"变成"你该补哪一块"。
> 3. **运行条件**：ChatGPT 要联网、要额度、会漂移；我们**零外部依赖**，一条 `uvicorn` 命令，考场断网照跑。

### Q2.2 "Isn't that just a nicer explanation? Why does the granularity matter pedagogically?"

**答（45 秒）**：
> 因为学生拿到"这题错了"之后的行为是**重刷这道题**，而拿到"你混淆了除斥期间和诉讼时效"之后的行为是**去补这两个概念的差异**。前者在考场上换个问法继续错，后者会迁移。
>
> 文献上这不新鲜：VanLehn (2011) 的元分析显示细粒度反馈的效应量接近人类导师；Koedinger et al. (2012) 把前置知识显式建模。我们的贡献不是发明这个理论，而是**用 36 个手工设计的陷阱，在零预算、零模型的条件下把它做出来**。这部分写在报告第 1.2 和第 5.3 节。

### Q2.3 "What is your actual novel contribution? Students often overclaim."

**答（35 秒）**：
> 我们不主张发明了新算法——诊断就是一次字典查找，这一点报告里明说了。我们的贡献是三项工程与设计工作：
> 1. **选项级陷阱的数据模型**（`OptionItem.trap_id → TrapDetail{title, desc, prereq, radar_hit}`），它把诊断从"推理"降级成"查表"，从而做到 5 ms、离线、可测试；
> 2. **一个可复现的零构建交付形态**（单进程单端口 + 145 个不依赖外部服务的测试）；
> 3. **一组诚实的实证数据**：12 个 MMLU 学科上图谱增强的正负结果（7 正 / 3 平 / 2 负），包含两个负值。
>
> 我们把它定位成 **feasibility evidence**，不是 research contribution。

## 3. 第三类追问：「10 个人怎么协同？你到底做了多少？」

### Q3.1 "What did each of you actually do? How did you divide the work?"

**答（40 秒）**：
> 两条线分开：
> - **软件线**：我是一个人写的（这是事实，我们会在 Appendix A 的 Group Workload Profile 里如实申报，不会假装十个人一起写代码）。
> - **报告线**：严格按官方七章切分，一人一章，9 人各负责一章/一节，我自己负责 Ch7 + 附录 A + 总集成。每份任务包里写清了页数、小节、素材路径、会被退回的写法，以及**导师可能问的 3 个问题**——保证换谁来答都能答上。
>
> 报告和代码的差异，我们**在 Appendix A 里如实反映**，不粉饰。

> ⚠️ **这是全场最危险的问题**。切勿说"我们分工很均衡"。官方 Appendix A 要求全员签署、口径 0% / +X% / −X%，虚报会被组员拒签并捅到 Course Coordinator。**正确的姿态是：承认集中，并说明我们把"知识集中"用报告分工的方式摊平了。**

### Q3.2 "If one person wrote the code, how is this group work?"

**答（40 秒）**：
> 我不辩护这一点，我说明我们的处理方式：
> 1. **不虚报**：Appendix A 会如实写代码主要由一人完成；
> 2. **把知识变成可被提问的共同资产**：组会前 24 小时随机抽人回答「你这章的核心论点是什么」「这个数字从哪来」，答不上来按"该章未完成"处理；
> 3. **每人对自己那章负责**：9 位组员各自署名 4–5 页，且每人的任务包里都有独立的论证任务（不是抄仓库文档）——比如张梓健必须自己写四条 Won't 的取舍理由，习羽赛必须自己解释为什么 UI 是那样设计的。
>
> 这件事我们做得不满意但做得诚实。**报告里能查到的每句话，都有人能当面讲清楚它是怎么来的。**

### Q3.3 "How do you know the report isn't AI-generated?"

**答（40 秒）**：
> 三个可检查的机制：
> 1. **随机抽问**：任何一章的核心论点，我们随机抽一个人现场讲；
> 2. **数字可追溯**：报告里每个数字都能追到仓库文件（题库、测试、CSV），AI 生成的内容通常数字对不上；
> 3. **主动写弱点**：报告里有专门的 Threats to Validity 节和 Limitations 节，AI 生成的项目通常不会主动交出这些。您可以只看第 6.6 节和第 7.2 节判断。

## 4. 第四类追问：「断网 / 欠费 / 数据没了会怎样？」

### Q4.1 "What happens if the network is down during the demo?"

**答（30 秒）**：
> 一切正常。演示路径**零外部依赖**：无数据库、无 LLM API、无云服务。前端静态文件由同一个 uvicorn 进程通过 `StaticFiles` 挂载在 `/`，API 挂 `/api`，同一端口同源。我们**主动**把云端 Neo4j 移出了演示链路（架构决策 ADR-05），理由就是它会休眠、考场可能断网。

### Q4.2 "What if your Neo4j instance expires or the API quota runs out?"

**答（35 秒）**：
> 演示不受影响——Neo4j 只在**离线评估**链路里，不在在线演示里。评估结果已经快照成 `final_systematic_report.csv` 提交在仓库里，报告第 6.3 节的每个数字都能追到那个文件。
>
> 我们如实承认**评估链路不可完全复现**（第 5.6.4 节写了），因为重跑需要云实例。所以我们的做法是：**结果快照随仓库提交，而不是让考官去重跑一个需要云账号的脚本。**

### Q4.3 "What happens if the user's browser cache holds an old version?" / "What about data loss?"

**答（30 秒）**：
> 缓存问题我们真实遇到过：一次更新后界面不刷新，修复方式是在静态资源引用上加版本号 query string（commit `09ae770`），并在报告第 5.1.3 节里作为真实工程细节写了进去。
>
> 数据方面：题库是**只读的 Python 源文件**，不存在"数据丢失"路径；学生作答记录保存在浏览器 `localStorage`，所以清缓存会丢历史——这是 ADR-07 的已知代价，我们把它列进了 Limitations，并给出了 JWT + 服务端存储的替代方案。

### Q4.4 "So is there a real security posture, or is this a toy?"

**答（35 秒）**：
> 是 toy，我们不假装不是。三处已知弱点我们主动写在了报告里：
> 1. `allow_origins=["*"]`（ADR-06）——生产化必须收紧；
> 2. `localStorage` 会话没有真正的权限边界（ADR-07）；
> 3. **一次真实的凭证泄露**：`graphrag/real_graph_engine.py` 曾硬编码 Neo4j 账号密码且进入了 git 历史。这件事我们发现了，做了三件事：移到环境变量、重置了 Aura 密码、在交付 ZIP 的全仓搜索里加了一条检查。
>
> 我认为**把泄露写进报告**比藏起来更负责——因为 git 历史是可查的，藏不住。

## 5. 第五类（高频但不在原四类里）：「这东西有用吗？数据呢？」

### Q5.1 "You claim graph augmentation helps. Show me."

**答（40 秒）**：
> 12 个 MMLU 学科，Base vs Ours：**7 个正提升、3 个持平、2 个负提升**。最强的三个：Professional Law +2.50pp、HS Computer Science +2.00pp、Public Relations +1.82pp。负的两个：HS Physics −1.32pp、HS US History −1.00pp。
>
> 我们对负值的解释是：物理需要多步数值推理，图谱的结构化约束在这里更像噪声；历史考的是时序关联，我们的边类型建模不足。**另外必须说明：单次采样、没有置信区间，±1pp 量级的差异不应解读为统计显著**——这句写在报告 6.3 和 6.6 里。

### Q5.2 "145 tests pass — so what? You wrote them yourself."

**答（30 秒）**：
> 说明不了系统正确，只说明**回归基线存在**。它的真实价值是：任何人改了后端，3.6 秒内就知道有没有碰坏别的。真正的"正确性"证据在 25 个**对抗性**测试函数里——那是我们主动攻击自己写的（不存在的 ID、非法选项、注入字符、类型混淆、并发轰炸、空库），其中一部分在开发初期真的抓到了 404/422 混用的缺陷。
>
> 另外第 6.5 节把测试结果**逐条映射回 14 条需求**，看的是覆盖而不是通过率。

### Q5.3 "What failed? What would you do differently?"

**答（45 秒）**：
> 三件事，都写在报告的 Limitations 和反思节里：
> 1. **RAGAS 指标没跑完**：评估链路依赖嵌入服务配额。我们选择如实写"未完成"，而不是放一组自己都不信的分数。
> 2. **图谱没进在线链路**：它证明了"有条件有用"，但只停在离线评估。这是工程判断（云端不可靠），也是遗憾。
> 3. **12 道题太小**：它足以证明机制可行，但不足以证明教学有效。真正该做的是先做一轮 20 人的对照实验再扩题库——我们没时间做，所以不把它写成结论。
>
> 如果重来一次，我会**先做 20 人的小规模对照测试，再决定要不要做图谱那条支线**。

## 6. 危险问题速查（会前 5 分钟扫一遍）

| 导师可能问 | 一句话答法 |
| :--- | :--- |
| "One sentence: what is it?" | 反馈挂在**你选的那个错误选项**上的刷题工具。 |
| "Novel?" | 没发明算法；贡献是选项级陷阱的数据模型 + 零依赖可复现交付 + 一组含负值的实证数据。 |
| "AI-generated?" | AI 在实现与初稿里，判断与取舍在我们这里；三个关键决策是我们下的。 |
| "10 人怎么分?" | 代码一人写（如实申报），报告一人一章，每人能被随机抽问。 |
| "断网?" | 演示零外部依赖，断网照跑；云端只在离线评估链路。 |
| "凭证泄露?" | 发生过，已移出环境变量、已重置 Aura 密码、已加 ZIP 检查，并写进报告。 |
| "MMLU 负值?" | 物理 −1.32pp、US History −1.00pp，原因是推理型与关联型任务，单次采样不显著——我们主动写了。 |
| "RAGAS?" | 没跑完，如实写明，不放自己不信的分数。 |
| "为什么不用 React / 微服务 / 数据库?" | 三条 ADR：迭代速度、单机演示、零外部依赖；每条都写了代价。 |
| "CORS 全开安全吗?" | 不安全，ADR-06 已声明，生产化必须收紧。 |

## 7. 三条永不越过的线（学术诚信）

1. **绝不虚构用户调研**（"我们做了 n=200 问卷"→ 一旦被问"问卷在哪"就崩）。真实口径：文献 + 竞品分析 + 组内 10 人非正式验证。
2. **绝不虚报 MMLU**（说"全部提升"→ 与报告第 6 章表格自相矛盾）。真实口径：7 正 / 3 平 / 2 负。
3. **绝不虚报分工**（Appendix A 要全员签署，虚报会被拒签并上报 Course Coordinator）。真实口径：如实申报，用"报告分工 + 随机抽问"抵消知识集中。

> 这三条不是道德说教，是**这门课最容易被判零分的三个点**。报告写得薄可以补，诚信出问题没有第二次机会。
